## 2. 关系 B 的成本模型（`[假设]`，全部未测量）

### 2.1 朴素双轨迹电路

若把两条轨迹都按 cap=50 图编码，并在电路内比较低级观察：

```
rows(B) ≈ 2 × rows(A) + rows(obs_compare) + rows(challenge_binding)
```

`[数学推导]` Cheesecloth 原文明确指出双执行会让 statement "twice the size required for validating a single execution"（见 RELATED_WORK_MATRIX §3.1），本估计与原文一致。

`[假设]` 量级外推（**仅供决策，不是实测**）：

| 项 | A 实测（cap=50） | B 粗估 | 依据 |
| --- | --- | --- | --- |
| prove | 6.9–7.7 s | ≈ 14–18 s | 2× 单轨迹 + 比较/绑定器件 |
| setup | 6.4/8.0/2.9 s | 约 2× 或略高（电路更大，k 可能 +1） | 同模板放大 |
| proof size | 7968 B | 同量级（Halo2 proof 与 k 弱相关） | 非线性但通常不翻倍 |
| 峰值内存 | 2183 MB | 可能 2× 或更多 | 两条 witness 同时驻留 |

`[待验证]` 关键不确定项：`Obs_L` 的比较器件成本取决于观察表示（固定长度位串 vs 哈希 vs 集合）。若观察是低级输出位串的逐位相等，成本与输出位数线性；若用哈希比较，需额外 Poseidon/SHA 电路。

### 2.2 两种 B 形态的成本差异（`[数学推导]`）

1. **证明者自选对**：`∃(x_H0,x_H1)` —— 成本同 §2.1，但如 RELATIONAL_PROPERTIES §3.2 所述**安全上平凡**（取相同对即可）。这是"便宜但无意义"。
2. **验证者挑战对**：把 `(x_H0,x_H1)` 绑定到公开输入 —— 成本增加一个挑战绑定器件，但避免平凡满足；单次仍只是抽样，非全称。这是"稍贵但仍非全称"。

两者都不产生经典 NI 保证。因此 `[推论]` 为 B 付 2× 成本换来的只是"特定对隐藏比较"，其价值完全依赖硬隐私需求。

## 3. 关系 C 的成本模型（`[假设]`；分两条路线）

### 3.1 路线 1：电路内枚举全部对

设秘密输入字母表大小 `|A_H| = a`，秘密输入串长度上界 `L_max = ℓ`，执行长度上界 `T_max = t`，状态空间 `|S| = N_s`。

```
需验证的执行次数  ≈ (a^ℓ)^2 = a^{2ℓ}
总电路规模        ≈ a^{2ℓ} × t × cost(δ)   （δ 为单步转移电路）
```

`[数学推导]` 这是 `∀x_H0 ∀x_H1` 的直接展开。以最小非平凡参数 `a=2, ℓ=4, t=50` 为例：`a^{2ℓ}=256` 次执行 × 50 步 = 12,800 步转移。若单步转移电路的约束量与一条 cap=50 图的单步相当，则约为单轨迹的数百倍量级。

`[假设]` 粗估：prove 可能达 `6.9 s × 10² ~ 10³` 量级（数十分钟至小时），内存可能超出 cap=200 的 20 GB 峰值数倍。

**结论（`[数学推导]`）**：路线 1 在本项目的 cap/k 框架下**不可行**，不应作为原型目标。

### 3.2 路线 2：证书路径（唯一可能可行）

把 C 改写为 `∃ cert : VerifyCert(M, cert)=1 ∧ VerifyCert ⇒ R_C(M)`（RELATIONAL_PROPERTIES §4.4）。

```
rows(C-cert) ≈ rows(M commitment) + rows(cert verification) + rows(implication gadget)
```

`[待验证]` 成本取决于证书类型：
- **前向闭包式证书**（类比 A 的 S）：若 NI 可归约为某个状态集合上的闭合条件，则成本接近 A 的 crossbar（O(N_s²) 或 O(N_s·|E|)）。
- **类型推导证书**：需把类型规则编码入电路，成本与规则数 × 状态数相关。
- **归纳不变量证书**：需编码归纳步骤验证，可能有额外量化结构。

`[假设]` 若采用最简闭包式证书且 `N_s ≈ 50`，rows 可能与 A 同量级或 2–3×，prove 约 `7–25 s`。**但这只是类比猜测，未测量。**

### 3.3 路线 2 的隐藏成本（`[待验证]`）

C 要隐藏的不只是两条轨迹，还包括模型 `M` 本身（否则明文验证证书即可）。这要求：
- `M` 的转移表被承诺并在电路内验证（Poseidon 承诺 + 逐次打开）；
- 或 `M` 是公开固定模型，只有 `x_H`/证书被隐藏。

若选择前者，成本随 `|S|×|A|` 的承诺与打开线性增长；若选择后者，则**验证者能看见模型**，需重新论证隐私命题是什么。两者都需要在原型前明确。

## 4. 五类机制的成本价值比（汇总，`[推论]`）

| 机制 | prove/检查成本 | 验证成本 | 隐私 | 新增价值是否抵成本 |
| --- | --- | --- | --- | --- |
| 明文检查 | 0.028–0.148 ms | 同左 | 无 | 无隐私需求时最优 |
| 承诺 + 签名 | 0.022–0.023 ms | 0.062–0.206 ms | 无 | 来源绑定，但不隐藏 |
| Halo2 A | 6.9–7.7 s（cap=50） | 48–56 ms + VK 重建 2.2–2.5 s | 隐藏图 | 仅在"必须隐藏图"时成立；该硬需求未建立 |
| Halo2 B（假设） | ≈14–18 s（未测） | 同量级 | 隐藏两轨迹 | 需硬隐私需求 + 挑战绑定；仍非全称 |
| Halo2 C（假设） | 枚举不可行；证书路径 ≈7–25 s（未测） | 同量级 | 隐藏轨迹/模型 | 需证书可靠性 + 模型锚定 + 硬隐私需求 |

**最终成本结论（`[推论]`）**：
1. A 的成本已被实测锁定，且停止条件 4/5 已给出强警示。
2. B 的朴素实现约 2× A，但安全上要么平凡、要么单点抽样；成本换来的保证有限。
3. C 的枚举路线不可行；证书路线是唯一可能方向，但成本、模型可信性、隐私需求三项都未闭合。
4. 因此**在本阶段不具备进入 Halo2 原型的成本依据**。任何后续原型必须先回答 DECISION.md 中列出的前置条件，并在预注册中冻结测量口径（避免再次出现 Phase 1B 与 1B.1 口径不一致的问题）。
