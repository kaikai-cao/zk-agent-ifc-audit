### 2.2 关系定义（任务 2，`[数学推导]`）

- A = `¬∃ h∈H,l∈Sinks_L: h⇝l`（单图内部性质）。
- B = `Obs_L(τ₀)=Obs_L(τ₁)`（**特定两实例**，非全称；自选对时平凡满足）。
- C = `∀x_L∀x_H0∀x_H1: Obs_L^{≤T}(M(x_L,x_H0))=Obs_L^{≤T}(M(x_L,x_H1))`（有界全称）。
- 三者**两两不等价**。C 是 SNARK 的**非原生形态**（`∀` 非 `∃`），必须改写为证书路径才可编码。

### 2.3 相关工作（任务 3，`[原文核验]`）

最关键的三个事实：

1. **Distributed Sentinel §4.8.1**（arXiv:2604.22879 原文）：已实现 `∃w: R(x,w)=b`，`w` 明确为 graph structure，Groth16，45.2/2.1 ms、192 B。**A 的通用结构被占据，事实清楚。**
2. **Cheesecloth**（arXiv:2301.01321 原文 §2.2/§5.2）：**已经在 ZK 语境下使用成对执行 noninterference 定义**；且已识别双执行导致电路翻倍、采用单执行+标签下近似规避。因此 B 的"两条轨迹比较"**不是新定义，也不是新的电路优化**。其证明方向为存在性漏洞证明，与 B/C 的合规方向相反。
3. **LLMbda**（arXiv:2602.20064 v2 原文摘要）：已有 Lean 机器检验的全称概率 noninterference 定理，覆盖整个演算与代码生成。**C 的"全称 NI"在形式化层面已有强近邻。**

其余（zk-MCP、FIDES、NeuroTaint、ZEKRA、SME、Pave、AttnNI）见 `RELATED_WORK_MATRIX.md`。专门检索**未发现**"ZK 证明全称 NI"的直接工作，但检索不构成不存在性证据，按 `[待验证]` HOLD。

**结论**：没有发现任何单一工作直接占据"隐藏轨迹/模型 + 有界全称 NI + 外部公开可验证"这一具体组合；但通用结构、成对定义、全称形式化三项分别已被占据。`[推论]` 若最终差别只是字段/对象替换，停止条件 3 将触发 NO-GO。

### 2.4 反例（任务 4，`[数学推导]`）

五个反例显示：
- A 在五例中最多条件识别两例，且条件来自采集粒度而非关系本身；
- B 存在**结构性盲点**（反例 2：第三条轨迹泄露），且其余识别能力依赖 `Obs_L` 与挑战绑定；
- C 形式最强，但五例中四例的识别能力取决于 `M`/`Obs_L` 的定义质量，**不取决于全称量词**。

**核心推论**：从 A 到 B/C 的研究增量主要不在密码学，而在**模型定义、观察函数、信任锚定**。若这部分不解决，写出的 Halo2 电路只是把不完整的语义做了 ZK 编码。

### 2.5 成本（任务 3 下，`[仓库记载]` + `[假设]`）

- A 已实测：cap=50 prove 6.9–7.7 s，明文 0.028–0.039 ms；cap=200 setup ≈477 s、峰值 20–22 GB。
- B 朴素估计约 2× A（未测）；但安全上要么平凡、要么单点抽样。
- C 枚举路线随 `a^{2ℓ}×t` 增长，`a=2,ℓ=4,t=50` 即约 12,800 步转移，**不可行**；证书路径是唯一可能方向，成本与模型锚定成本均未闭合。

因此**不具备进入 Halo2 原型的成本依据**。

## 3. 必须完成的前置修订（REVISE 的具体含义）

以下每一项都是**可证伪的闸门**，不是建议。任一项无法闭合 → 转 NO-GO。

### R1 — 把 B 从"研究问题答案"降级为"必要但不足的单例检验"
- 明确写定：B **不**回答"不同秘密输入会造成不允许差异吗"，只回答"这两个被指定的秘密输入没造成差异"。
- 若保留 B，必须把 `(x_H0,x_H1)` 绑定到公开输入由验证者挑战，禁止证明者自选；否则 B 平凡。
- 不得用 B 的通过宣称 NI 或 C。

### R2 — 把研究目标定为 C，并显式固定 C 的五个边界
必须写出并冻结：
1. `|S|` 状态空间上界；
2. `L_max` 秘密输入串长度；
3. `T_max` 执行长度/步数上界；
4. 确定性 or 不确定性（及不确定性下的集合/概率语义）；
5. 终止与超时行为（`⊥` 是否可观察）。
缺任何一项，C 命题无定义，不进入实现。

### R3 — 设计 NI 证书路径，而非电路内枚举
- 给出证书 `cert` 的形式定义与 `VerifyCert ⇒ R_C(M)` 的可靠性论证（可先是非形式化的归约说明，但必须可检查）。
- 论证证书相对 Cheesecloth storage-labeling（`[原文核验]`）与 LLMbda 类型系统（`[原文核验]`）的**额外价值**是什么。若答案只是"字段更多/对象换成 Agent 图"，转 NO-GO。

### R4 — 修复信任模型：M 的来源与 Obs_L 的边界
- 明确 `M` 从何而来：公开形式化模型 / 从轨迹归纳 / 二者混合。
- 若从轨迹归纳，必须正面回答采集器漏记问题如何从图层面**上移到模型层面**（反例 D 的模型版）。
- 显式定义 `Obs_L`：是否含工具身份、调用参数、外部副作用、事件结构、时序（反例 3/4/5）。定义缺失则 B/C 无判定标准。
- 正面记录：ZK 不减少采集器信任、不证明标签真实性、不证明运行时执行真实性（`[仓库记载]` SECURITY_MODEL §2–§4）。

### R5 — 建立"必须隐藏"的硬隐私需求
这是停止条件 5 的核心，也是 B/C 相对明文比较的**唯一**新增价值来源（`[推论]`）。必须给出具体场景说明：
- 为什么验证者**不能**看到两条轨迹 / 模型 / 证书？
- 若明文比较 + 签名即可达到同样的审计结论，则 ZK 版本没有新增价值 → NO-GO。
- 不得用"零知识听起来更好"作为需求论证。

### R6 — 预注册与口径冻结
若 R1–R5 闭合后决定原型：
- 新开独立阶段与分支，冻结 `Obs_L`、`M`、证书、cap/k、计时口径；
- 避免重演 Phase 1B 与 1B.1 的 `verify_ms` 口径冲突（`[仓库记载]`）；
- 不覆盖 `main` 上的冻结基线、不改写已通过项。

| 结果 | 条件 |

| **GO** | R1–R5 全部闭合并有书面论证；C 的证书路径有非平凡可靠性论证；相对 Cheesecloth/LLMbda/Distributed Sentinel 有新可证性质（非字段组合）；硬隐私需求有具体场景；成本估计在可接受上限内且有预注册。 |

**默认规则**：REVISE 不是无限期 HOLD。下一阶段必须针对 R1–R5 给出书面结论；若结论是否定的，直接转 NO-GO，不再寻找新的组合式卖点。

## 5. 对用户最终问题的直接回答

> 过去："给定一个隐藏的 Agent 会话图，如何证明它没有违反信息流策略？"
> 现在："能否在不暴露秘密输入、执行轨迹和内部信息流的前提下，向外部审计者证明不同秘密输入不会造成不允许的公开行为差异？"

**回答（`[数学推导]` + `[推论]`）**：

1. **这个问题比 A 更有理论价值，而且不是同一个问题。** A 是单条已记录轨迹的图内性质；新问题跨执行、接近经典 IFC 的核心。这个判断成立。
2. **但"不同秘密输入"的自然形式是有界全称 C，不是双轨迹 B。** 若只做 B，回答的只是"这一对输入没造成差异"——反例 2 说明第三条轨迹可以照样泄露。把 B 称为该问题的答案会构成量词偷换。
3. **双轨迹、有限模型全称、程序语义证明三者的差异已在 `RELATIONAL_PROPERTIES.md` 澄清**：B 是单例、非全称；C 是全称但非 SNARK 原生、需证书；程序语义全称 NI 已有 LLMbda 的 Lean 机器检验强近邻（`[原文核验]`）。
4. **因此不能预先认定这个问题值得做。** 它值得**继续定义**，但不值得**现在写 Halo2 电路**。决定其价值的是 R3（证书的新可证性质）、R4（模型与观察边界）、R5（硬隐私需求）三项，而不是电路实现的复杂度。

一句话结论：**问题问对了，但答案还不是电路。** 先按 R1–R5 把关系与信任模型改到可辩护，再决定是否写 Halo2；改不动就 NO-GO。
