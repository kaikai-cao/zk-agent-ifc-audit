# Phase 1C — 任务 4：最小反例集与 A/B/C 识别能力

证据标记：`[数学推导]` = 由三个关系的定义直接推出；`[仓库记载]` = 与仓库已有反例 D/E 对应；`[设计假设]` = 反例场景为说明性构造，非实测 Agent 运行。

每个反例都按同一模板给出：场景 → 为何发生 → A/B/C 能否识别 → 对研究决策的含义。

判定口径：
- **识别** = 该关系的结构本身会导致反例被拒绝或命题不成立；
- **不识别** = 该关系的定义域/量词不覆盖反例中的差异；
- **条件识别** = 只有在额外假设（如观察函数定义、挑战绑定、模型保真度）成立时才识别，这些假设本身不在关系内。

## 反例 1：单轨迹合规，但系统在另一组输入下泄露

`[设计假设]` `[仓库记载]`（对应反例 D 的跨输入版本）

### 场景
程序 `P` 接收公开输入 `x_L = "summarize_document"` 与秘密输入 `x_H ∈ {doc_safe, doc_malicious}`。
- 运行 `τ₀ = P(x_L, doc_safe)`：文档无敏感内容，采集器构造的图 `G₀` 无 High→Low 路径。
- 运行 `τ₁ = P(x_L, doc_malicious)`：文档含机密 token，模型输出把它传给 `public_sink`，`G₁` 有 High→Low 路径。

审计者只对 `τ₀` 取证并获得证明。

### A 能否识别：**不识别**
`[数学推导]` `R_A(G₀)=1`，因为 `G₀` 内部无 High→Low 路径。A 的量词只覆盖**一条已记录的图**，对 `τ₁` 无任何断言。这与仓库反例 D（漏边）不同：这里采集器没有漏记，只是**没有发生在被审计的那次运行里**。

### B 能否识别：**条件识别**
`[数学推导]` 若证明者自选对并取 `x_H0 = x_H1 = doc_safe`，则 `Obs_L(τ₀)=Obs_L(τ₀)` 平凡成立，B 接受。若验证者强制挑战对为 `(doc_safe, doc_malicious)`，则 `Obs_L` 不同，B 拒绝。**关键：识别能力来自挑战绑定，不来自 B 的关系本身。**

### C 能否识别：**条件识别（需模型含两种输入）**
`[数学推导]` 若 `M` 的 `A_H` 同时含 `doc_safe` 与 `doc_malicious`，则全称命题被 `τ₁` 违反，C 不成立。若 `M` 只建模了 `doc_safe`（例如从 `G₀` 归纳得到），C 同样不识别。**识别能力来自 M 的输入域覆盖，不来自全称量词本身。**

### 对决策的含义
这是"Trace-level safety ≠ Semantic noninterference"的最直接例证。它说明 A 的合规证明**不能**被写成"系统不会泄露"。同时说明 B/C 的价值取决于"是否检查了正确的输入/模型"，而非仅取决于量词形式。

## 反例 2：两条轨迹低级输出相同，但第三条轨迹泄露

`[设计假设]`

### 场景
秘密输入空间有三个值 `x_H ∈ {a, b, c}`：
- `Obs_L(P(x_L,a)) = "OK"`
- `Obs_L(P(x_L,b)) = "OK"`
- `Obs_L(P(x_L,c)) = "SECRET_TOKEN"`

审计者恰好取证并比较了前两条。

### A 能否识别：**不识别**
`[数学推导]` 任取 `G_a` 或 `G_b`，若其内部无 High→Low 路径则 A 接受。A 根本不比较两条轨迹。

### B 能否识别：**不识别（结构性）**
`[数学推导]` `R_B(τ_a, τ_b)=1`，因为 `"OK" = "OK"`。B 的定义只含**两条**轨迹，第三条 `τ_c` 不在其定义域内。即使换任意一对，只要没选中含 `c` 的对，B 都接受。这是 B 作为"关系性质"的**结构性盲点**：一对相等不蕴含全体相等。

### C 能否识别：**条件识别**
`[数学推导]` 若 `c ∈ A_H`（模型输入域包含 c），则 `∀` 命题被违反，C 不成立。若模型的秘密输入域被限制为 `{a,b}`（例如从两次被审计的运行归纳），C 接受。**全称只在显式声明的有限域内有意义。**

### 对决策的含义
B 不能回答用户最终问题中的"不同秘密输入"（复数、隐含全体）。把 B 包装成该问题的答案会造成量词偷换。只有 C 在**明确模型输入域**后才具备回答该问题的形式。

## 反例 3：图上没有 High→Low 路径，但存在未建模的隐式信息流

`[设计假设]` `[仓库记载]`（对应停止条件 1 与 NeuroTaint 指出的语义转换/隐式因果）

### 场景
High 输入 `secret ∈ {0,1}` 不改变任何被记录的数据内容，但控制分支：
```
if secret == 1: call tool_A()   # 合法工具
else:          call tool_B()   # 合法工具
```
采集器只记录 `data` 依赖边（内容传播），不记录 `control` 依赖边。图中没有从 High 源到 Low sink 的路径：两个分支的工具都是公开允许的，返回内容也不含秘密。然而外部审计者能从"调用了哪个工具"推断 `secret`。

### A 能否识别：**不识别**
`[数学推导]` `R_A(G)=1`，因为 `G` 中 High 节点没有到 Low sink 的路径。关系 `R_A` 的定义域是 `G=(V,E,L,type)`；未进入 `E` 的隐式因果边不在定义域内。这与 `docs/TRACE_IFC_RELATION.md` §1 允许 `control` 边种类但采集器可能漏记的边界一致。

### B 能否识别：**条件识别**
`[数学推导]` 若 `Obs_L` 包含"调用了哪个工具"，则 `Obs_L(τ_0) ≠ Obs_L(τ_1)`，B 拒绝。若 `Obs_L` 只定义为公开 sink 的**内容**，则两轨迹输出相同，B 接受。**识别能力完全取决于观察函数 `Obs_L` 的定义，而 `Obs_L` 不是 B 关系的一部分。**

### C 能否识别：**条件识别**
`[数学推导]` 若 `M` 的转移关系 `T` 建模了分支对工具选择的影响，且 `obs_L` 包含工具身份，则 C 不成立。若 `M` 是从同一张缺边图归纳得到的，C 与 A 一样不识别。**全称量词不能弥补模型保真度不足。**

### 对决策的含义
这是停止条件 1 的核心：边定义不完整时，**任何**图谓词（A）或图归纳模型（C）都继承该不完整。ZKP 证明的是"被承诺图的合规"，不是"真实执行无隐式流"。B/C 若要把隐式流纳入，必须先扩展 `Obs_L` 与 `M`，这属于模型定义工作而非密码学工作。

## 反例 4：两条轨迹表面输出相同，但工具副作用不同

`[设计假设]`

### 场景
```
τ₀: secret=0 → call email_send(to="attacker@x") → sink 返回 "SENT"
τ₁: secret=1 → call email_send(to="user@y")     → sink 返回 "SENT"
```
公开 sink 内容都是 `"SENT"`，但外部副作用（收件人）不同，且收件人地址编码了秘密。

### A 能否识别：**条件识别（弱）**
`[数学推导]` 若采集器把 `email_send` 的参数记录为 `tool_invocation` 节点且其标签来自 High 源，则 `G` 中可能出现 High→Low 路径，A 拒绝。若采集器只记录"调用发生"而不记录参数（仓库安全模型：`docs/SECURITY_MODEL.md` §2.4 明确 ZKP 不证明调用参数未被篡改），则 A 接受。**识别依赖采集粒度，不依赖 A 本身。**

### B 能否识别：**条件识别**
`[数学推导]` 若 `Obs_L` 含副作用（收件人），B 拒绝；若 `Obs_L` 只含 sink 返回值，B 接受。这与反例 3 同源：**观察投影的选择决定 B 的判定**。

### C 能否识别：**条件识别**
`[数学推导]` 若 `M` 的状态 `S` 包含工具外部状态（收件人列表）且 `obs_L` 投影到该状态，则 C 不成立。若 `M` 是无副作用的纯函数模型，C 接受。

### 对决策的含义
"不允许的公开行为差异"必须先定义 `Obs_L` 的边界：什么算"公开行为"。这是策略/语义问题，不是 ZK 问题。若把副作用纳入 `Obs_L`，则 `M` 必须建模外部世界状态，模型可信性与成本都显著上升（`[待验证]`）。

## 反例 5：两条轨迹事件结构不同，简单节点逐一比较失效

`[设计假设]`

### 场景
```
τ₀: [confidential_source] → [model_output] → [tool_invocation] → [public_sink]      （4 节点）
τ₁: [confidential_source] → [model_output] → [tool_A] → [tool_B] → [public_sink]    （5 节点）
```
两条轨迹的公开 sink 输出相同，但中间执行结构不同：τ₁ 多一次工具调用，且该调用读取了 High 源但结果未直接输出。

### A 能否识别：**条件识别**
`[数学推导]` 单独看 `G₁`：若 High→tool_A→tool_B→sink 的路径存在，A 拒绝；若 tool_B 的结果未连到 sink，A 接受。A 对"结构不同"本身不敏感，只对路径敏感。

### B 能否识别：**条件识别（实现依赖）**
`[数学推导]` 若 B 的实现是**节点按位置逐一比较**（`leaf[i] == leaf[i]`），则：
- 节点数不同时，填充空叶可能导致假相等或假不等；
- 即使节点数相同，`τ₀` 的 `tool_invocation` 与 `τ₁` 的 `tool_A` 在索引 2 上不同，比较会失败——但这种失败是**结构差异**，不是**观察差异**。
因此逐节点比较既可能漏检（填充后相等）也可能误检（结构不同但观察相同）。`[数学推导]` 正确的比较必须基于**语义观察等价**（trace equivalence / bisimulation），而非语法节点对齐。

### C 能否识别：**条件识别**
`[数学推导]` 若 `M` 用集合语义 `Obs_L^{set}`（不确定性/多路径）并比较观察集合，则结构差异本身不构成差异，C 按观察结果判定。若 `M` 把事件结构本身纳入 `obs_L`，则 C 拒绝。**再次说明 `Obs_L` 定义是先于关系的选择。**

### 对决策的含义
这是 B 的一个**工程陷阱**：若未来实现 B，"两条轨迹相等"的朴素编码（逐叶子比较）在结构上不成立。必须先决定观察等价的语义定义（输出位串相等、trace set 相等、还是 bisimulation），再设计电路。Cheesecloth 用 storage labeling 规避双执行比较的做法（`[原文核验]`，见 RELATED_WORK_MATRIX §3.1）是已有先例，值得参考而非重新发明。

## 6. 汇总表：A/B/C 识别能力

| 反例 | 核心差异 | A | B | C | 识别能力的真正来源 |
| --- | --- | --- | --- | --- | --- |
| 1. 另一输入泄露 | 跨运行输入覆盖 | 不识别 | 条件（挑战绑定） | 条件（M 输入域） | 输入域覆盖 / 挑战绑定 |
| 2. 第三条轨迹泄露 | 全体 vs 一对 | 不识别 | **不识别（结构性）** | 条件（M 输入域） | 全称量词的范围 |
| 3. 未建模隐式流 | 边/模型保真度 | 不识别 | 条件（Obs_L） | 条件（M 保真度） | `Obs_L` 与 `M` 的定义 |
| 4. 副作用不同 | 公开行为边界 | 条件（采集粒度） | 条件（Obs_L） | 条件（状态/投影） | `Obs_L` 是否含副作用 |
| 5. 事件结构不同 | 语法 vs 语义等价 | 条件（路径） | 条件（比较语义） | 条件（观察语义） | 观察等价的形式定义 |

### 总体结论（`[数学推导]`）

1. **A 在五个反例中最多条件识别 2 个，且条件都来自采集粒度/边定义，不是 A 的关系本身。** A 作为"系统不泄露"的证据是不充分的。
2. **B 有一个结构性盲点（反例 2）**，且其余识别能力依赖 `Obs_L` 与挑战绑定。B 单独不构成全称性质。
3. **C 的形式最强，但五个反例中有四个的识别能力取决于 `M`/`Obs_L` 的定义质量，而非全称量词。** 全称只在模型可信、观察边界正确时才有意义。
4. 因此：**从 A 推进到 B/C 的研究增量，主要不在密码学，而在"模型定义 + 观察函数 + 信任锚定"。** 若这部分不解决，即使写出 Halo2 电路，也只是把不完整的语义做了 ZK 编码。`[推论]`
