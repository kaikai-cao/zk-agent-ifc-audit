# Phase 1C — 任务 2：三个候选证明关系的数学定义

证据标记：`[源码/文档核验]`、`[数学推导]`、`[待验证/假设]`。本文件只做定义与逻辑分析，不运行实验、不修改电路。

---

## 0. 贯穿全文的核心区分

> **Trace-level safety ≠ Semantic noninterference**（`[数学推导]`）

当前项目证明的是"**这一条已经被记录下来的执行图**没有 High→Low 路径"。这是一个关于**单个已存在对象**的**存在性/单实例**性质。经典 Noninterference（NI）是关于**程序/系统在所有输入下行为**的**全称、跨执行**性质。两者的量词结构不同，不能由一个推出另一个。

用一个统一记号写清楚三个候选的量词结构：

- A：`∃ witness G`（隐藏的单图），使得 `Safe(G)` —— 单图内部性质。
- B：`∃ witness (τ₀,τ₁)`（两条隐藏轨迹），使得 `Obs_L(τ₀)=Obs_L(τ₁)` —— 特定两实例之间。
- C：`∀ x_H0,x_H1`（在某个有限模型 M 的**全部允许输入**上），`Obs_L(M(x_L,x_H0))=Obs_L(M(x_L,x_H1))` —— 有界全称。

SNARK 的自然形态是 `∃w : R(x,w)=1`（NP 型关系）。C 的全称量词**不是** SNARK 的原生形态；这是本阶段最重要的成本与可行性分水岭（详见 COST_MODEL.md 与 DECISION.md）。

## 2. 关系 A：单轨迹 Trace-IFC（`[源码/文档核验]`，定义见 `docs/TRACE_IFC_RELATION.md` §3、§6）

### 2.1 数学定义

```
R_A(G) = 1  ⟺  ¬∃ h ∈ H, l ∈ Sinks_L : h ⇝ l
```

等价的前向闭包判据（电路采用）：存在 `S ⊆ V` 满足

```
(C1) ∀ v : L(v)=High                  ⇒ S[v]=1
(C2) ∀ (u,v,k) ∈ E : S[u]=1           ⇒ S[v]=1     （即 S[u]·(1−S[v])=0）
(C3) ∀ v : type(v)=public_sink ∧ L(v)=Low ⇒ S[v]=0
(C4) ∀ v : S[v] ∈ {0,1}
```

`[数学推导]` C1–C3 与"无 High→Low-sink 路径"等价：若有路径 `v₀→…→v_m`，C1 给 `S[v₀]=1`，C2 归纳给 `S[v_m]=1`，与 C3 矛盾；反之取 S 为 High 节点前向可达集即满足 C1–C3。

### 2.2 作为 ZK 关系的精确形态

`[源码/文档核验]` 当前电路证明的不是裸 `R_A(G)`，而是：

```
R_A^ZK(x, w) = 1 ⟺
    EncodingValid(w.G, cap)                                   # 类型/标签/索引/数量
  ∧ H(DOMAIN_BLIND+cap, MerkleRoot(Enc(w.G)), w.blind) == x.C   # 盲化承诺
  ∧ BindingFields(w) == (x.policy_id, x.session_id, x.nonce, x.collector_id)
  ∧ ForwardClosureExists(w.G, w.S)                            # C1–C4
```

公开输入 `x=(C, policy_id, session_id, nonce, collector_id)`；见证 `w` 含图、标签、S、Merkle 路径、采集器认证字段。`Verify(x,π)=1` 在 soundness 假设下意味着：**存在一个被承诺的隐藏图满足 Trace-IFC**。

### 2.3 边界（`[源码/文档核验]`，`docs/PROBLEM_DEFINITION.md` N1–N4）

- A 明确**不证明** N1（经典两运行 NI）、N3（运行时执行真实性）、采集器无漏记（反例 D）、标签来源真实（反例 E）。
- A 的量词是"对一条已记录图的内部所有路径"；它不对"未发生的执行"或"另一组秘密输入"作任何断言。

## 3. 关系 B：双轨迹关系非干扰（特定两实例）

### 3.1 数学定义

给定**同一公开输入** `x_L` 与两个秘密输入 `x_H0, x_H1`：

```
τ₀ = P(x_L, x_H0)
τ₁ = P(x_L, x_H1)

R_B(τ₀, τ₁) = 1  ⟺  Obs_L(τ₀) = Obs_L(τ₁)
```

### 3.2 必须写清的量词边界（`[数学推导]`）

**这是两个具体执行实例之间的低级观察等价。它不自动证明经典 NI。** 原因有三层：

1. **固定对 vs 全称对**：经典 NI 要求 `∀ x_L ∀ x_H0 ∀ x_H1 : Obs_L(...) = Obs_L(...)`。B 只检查**一对**已给定的 `(x_H0, x_H1)`。
2. **存在性见证的脆弱性**：若把 `x_H0, x_H1` 放进见证 `w`，则 SNARK 证明 `∃(x_H0,x_H1,τ₀,τ₁) : τᵢ=P(x_L,x_Hᵢ) ∧ Obs_L(τ₀)=Obs_L(τ₁)`。此时证明者取 `x_H0 = x_H1` 即可**平凡满足**——B 退化为同义反复，不含任何安全信息。要让 B 非平凡，必须把 `(x_H0, x_H1)` 作为**验证者指定/挑战并绑定到公开输入**的值，禁止证明者自选。
3. **即便挑战绑定，仍是单点抽样**：一次挑战通过只说明"这一对没泄露"；其他对可能泄露。`[待验证]` 若改为随机挑战多次，得到的是概率性 assurance，其置信度取决于秘密输入空间大小与泄露对的比例，不构成确定性全称证明。

### 3.3 与经典 NI 的关系（`[数学推导]`）

```
R_B(τ₀,τ₁)=1  ⇏  NI(P)
NI(P)          ⇒  R_B(τ₀,τ₁)=1   （对任意挑战对，前提是可执行语义一致）
```

即 B 是 NI 的**必要但远非充分**的单例检验。

### 3.4 隐藏性需求

要在隐藏设置下证明 B，`τ₀` 与 `τ₁` 都必须对验证者隐藏（否则直接比较明文即可）。这正是用户提出的研究问题："不暴露秘密输入、执行轨迹和内部信息流，向外部审计者证明不同秘密输入不会造成不允许的公开行为差异。"

`[数学推导]` B 的价值命题必须回答：**验证者为什么不能看见这两条轨迹？** 若没有独立的硬隐私需求，明文比较 + 签名即可完成同一判断，B 的 ZK 版本只剩成本劣势。

## 4. 关系 C：有限模型上的有界全称非干扰

### 4.1 有限模型的显式定义（`[数学推导]`；这是为消除"模型可信性"含糊而必须固定的部分）

令

```
M = (S, A, T, s₀, obs_L)
```

- `S`：有限状态集合，`|S| = N_s`（必须显式声明上界）。
- `A`：动作/输入字母表，划分为公开 `A_L` 与秘密 `A_H`。
- `T ⊆ S × A × S`：转移关系。**必须声明确定性或不确定性**：
  - 确定性：`T` 为函数 `δ:S×A→S`，`M(x)` 唯一。
  - 不确定性：`T` 为关系，`Runs(M,x)` 为执行集合，观察为集合 `Obs_L^set(M,x) ⊆ O_L`。
- `s₀`：初始状态（可含 `x_L` 作为公开参数）。
- `H ≤ T_max`：执行长度上界（步数或时间片），`T_max` 必须显式固定。
- `obs_L : S → O_L`：状态到低级观察的投影。
- **终止行为**：必须显式处理。推荐 `O_L^* = O_L ∪ {⊥}`（`⊥`=不终止/超时），并规定"无输出"与"超时"是否可区分；否则全称命题在发散执行上无定义。
- **不确定性下的等价定义**：需明确采用
  - (a) 可能性语义（possibilistic）：`Obs_L^set(M,x_H0) = Obs_L^set(M,x_H1)`（集合相等）；或
  - (b) 几乎确保（almost-sure）/ 定量语义。
  本阶段选择 (a) 作为最简可判定版本，并把 (b) 记为开放项。

### 4.2 数学定义

```
R_C(M) = 1  ⟺  ∀ x_L ∈ X_L, ∀ x_H0, x_H1 ∈ A_H^* (长度 ≤ L_max) :
                 Obs_L^{≤T_max}(M(x_L, x_H0)) = Obs_L^{≤T_max}(M(x_L, x_H1))
```

其中 `Obs_L^{≤T_max}(M(x))` 是执行在 `T_max` 步内的低级观察（不确定性下为集合）。

### 4.3 与经典 NI 的关系（`[数学推导]`）

- C 若取 `X_L` 为全体公开输入、`A_H^*` 为全体秘密输入串、`T_max → ∞`、`M` 为真实系统语义，则 C **退化为经典 NI**（`[数学推导]`，经典定义见 Goguen–Meseguer 1982 传统）。
- 本阶段的 C 是**有界版本**：`|S|`、`L_max`、`T_max`、确定性/不确定性、终止处理都被显式限制。因此 C 成立**只在这些边界内**成立；把 C 写成"系统满足 NI"是越界陈述。
- `R_C(M)=1 ⇒ R_B(任意挑战对)=1`（`[数学推导]`）；反向不成立。

### 4.4 作为 ZK 关系的根本困难（`[数学推导]`；关键结论）

SNARK 证明 NP 型关系 `∃w : R(x,w)=1`。C 是 `∀` 命题，属于 coNP/Π 型结构，不能原生编码为"存在一个见证使电路可满足"。可行路径只有两类：

1. **枚举路径**：在电路内枚举全部 `(x_H0,x_H1)` 对并逐一执行 `M`。成本随 `|A_H|^{2·L_max} × T_max × |S|` 增长——`[待验证]` 该规模在 cap=50 级别已可能不可承受（量级分析见 COST_MODEL.md），且需要把 M 的完整转移表放进电路或承诺。
2. **证书路径**：把 C 改写为 `∃ cert : VerifyCert(M, cert)=1 ∧ VerifyCert ⇒ R_C(M)`。例如归纳不变量、类型推导、前向闭包式证书（类比 A 中的 S）。此时 ZK 证明的是"存在一个可在电路内高效检验的证书"，**而全称性由证书的可靠性引理保证，不是由电路枚举保证**。

`[推论]` 路径 2 是唯一在成本上可能可行的方向，但它把研究重心从"证明系统语义"转移到"设计可验证的 NI 证书 + 证明该证书蕴含 C"。这与 FIDES/LLMbda 的类型系统路线在方法上同源，差别在于证书被隐藏并用 ZK 验证。

### 4.5 模型可信性（`[待验证/假设]`）

`M` 从何而来？若 `M` 由采集器记录的轨迹归纳得到，则"采集器是否漏记/错标"问题从图层面**上移到模型层面**，并未消失。若 `M` 是程序的公开形式化模型，则模型与真实运行的一致性（N3）属于信任边界之外。C 的研究价值取决于能否给出 `M` 的可接受锚定方式；本阶段不预设已解决。

## 5. 三者的严格层级（`[数学推导]`）

在"同一公开输入、语义一致、观察函数相同"的前提下：

```
R_C(M)=1  ⇒  ∀ 由 M 生成的 (τ₀,τ₁): R_B(τ₀,τ₁)=1
R_B(τ₀,τ₁)=1  ⇏  R_C(M)=1          （单点不蕴含全称）
R_A(G)=1  ⇏  R_B(τ₀,τ₁)=1          （单图合规不代表跨输入观察等价）
R_B(τ₀,τ₁)=1  ⇏  R_A(G)=1          （观察相等不代表图无 High→Low 路径：可两图都泄露同样内容）
```

**四个性质两两不等价**。这是 Phase 1C 的核心技术结论：把 A 称为"非干扰证明"是错误命名；把 B 称为"关系性质"必须同时说明它不是全称；只有 C（在有界且模型可信时）接近经典 NI。

## 6. 对用户最终问题的直接回答（定义层面）

> "能否在不暴露秘密输入、执行轨迹和内部信息流的前提下，向外部审计者证明不同秘密输入不会造成不允许的公开行为差异？"

- `[数学推导]` 这个问题在定义层面**成立且严格强于 A**：它对应 B 的隐藏版或 C 的隐藏版，量词从"单图"推进到"跨执行/全称"。理论上更接近经典 IFC 核心。
- `[数学推导]` 但"不同秘密输入不会造成不允许的公开行为差异"若指**任意**秘密输入，则形式是 C 的全称命题，不是 B 的双轨迹命题；把 B 包装成该问题的答案会构成量词偷换。
- `[待验证]` 这个问题是否**值得做**，取决于三件事：C 的证书路径能否在电路内高效验证；`M` 的可信锚定；以及"验证者不能看见轨迹/模型"的硬隐私需求是否真实存在。这三点在本阶段尚未闭合，因此**不能预先认定 GO**。
