# Phase 1D.2 — 三种证书对象的统一比较矩阵

证据标记：`[定义]`、`[数学推导]`、`[标准结论]`、`[待验证]`。

> **成本三分**：本文件严格区分
> (G) **生成证书的成本**（证明者本地）；
> (V) **普通验证者检查证书的成本**（公开算法）；
> (S) **SNARK 电路中验证证书的成本**（约束数/证明生成）。
> **不可把普通算法复杂度直接等同于 SNARK 电路复杂度。**

---

## 1. 主比较表（任务包要求的十维）

| 比较维度 | State relation (`I_k`) | Trace automata (NFA/DFA) | Finite language (`L_T`) |
| --- | --- | --- | --- |
| **目标性质** | 存在满足约束的有界弱互模拟关系 ⇒ `C_T` | 分层观察轨迹自动机语言等价 `L(A_T⁰)=L(A_T¹)` ⇔ `C_T`（1D.2.1 分层定义） | 有限观察语言集合相等 `L₀=L₁` ⇔ `C_T` |
| **对 trace equivalence 的完备性** | **否**（真充分非必要；反例见 §STATE §2） | **是**（DFA 化后语言相等；子集构造合并状态） | **是**（定义即语言相等） |
| **证书规模** | 显式 `O(\|S\|²·T)`；简洁 `I` 可解耦 | 分层 NFA `O(\|S\|·(T+1))`；DFA 最坏 `2^{\|S\|(T+1)}`；深度 trie 最坏 `\|Λ̂\|^T`（1D.2.1 更新） | trie 最坏 `\|Λ̂\|^{T+1}`；DAG/最小 DFA 较小 |
| **验证复杂度（普通 V）** | 约束检查多项式（依赖 `I` 表示） | DFA 乘积可达 `O(\|Q₀\|\|Q₁\|\|Λ̂\|)`；一般 NFA 等价 PSPACE-complete（不推出证书大小下界，§3.1） | 逐串/同构比较；依赖表示 |
| **非确定性支持** | ∀∃ 双向全关系，原生支持 | NFA 原生；DFA 需子集构造 | 集合原生（含所有 nondet 轨迹） |
| **隐藏模型能力** | `I_k`/`→` 可作见证隐藏；需承诺绑定 | 自动机转移表可承诺隐藏；需绑定 | 语言表示可承诺隐藏；需绑定 |
| **是否需要模型承诺** | **是**（绑定 `→` 与 `I_k`，防换模型/漏后继） | **是**（绑定自动机与 `C_M`） | **是**（绑定表示与 `C_M`） |
| **模型真实性依赖** | 是（ZK 不解决） | 是（ZK 不解决） | 是（ZK 不解决） |
| **ZK 的实际增益** | 未建立（内核是标准互模拟） | 未建立（内核是标准 DFA 等价） | 未建立（内核是集合比较） |
| **主要局限** | 不完备；等价时证书可能不存在 | 子集构造最坏指数；PSPACE 判定 | 规模对 `T` 指数；全称化仍需 `\|X_H\|²` |

## 2. 三种成本的分项估算（`[数学推导]`）

设 `N=|S|`, `A=|Λ̂|`, `K=|X_H|`, `T`=可观察步数上界, `H=|X_H|²`（高输入对数）。

### 2.1 State relation `I_k`

| 成本类型 | 估算 | 说明 |
| --- | --- | --- |
| **(G) 生成** | 寻找 `I₀..I_T`；显式 `O(N²T)` 项，简洁 `I` 可更小 | 证明者需构造关系与后继配对函数 |
| **(V) 普通验证** | `O(N²·T·A)` 约束检查（显式表示） | 公开模型上的多项式检查 |
| **(S) SNARK 电路** | 与 (V) 同阶约束 + 承诺打开/查找论证开销 | 电路大小随 `N²T`；`I_k` 若简洁可压缩，但 ∀∃ 查询仍需逐状态约束 |

### 2.2 Trace automata（以 DFA 路线为例）

设分层 NFA 状态数 `N_T = N·(T+1)+1`（`N=|S|`，计数层来自 `TRACE_AUTOMATA_CERTIFICATE.md` §1）。

| 成本类型 | 估算 | 说明 |
| --- | --- | --- |
| **(G) 生成** | 子集构造最坏 `O(2^{N_T})`；最小化 `O(A·n log n)` | 分层 NFA 输入（原模型）时指数风险真实，`T` 进入指数 |
| **(V) 普通验证** | `O(\|Q₀\|\|Q₁\|A)` 乘积可达 | 多项式，但 `Qᵢ` 最坏 `2^{N_T}` |
| **(S) SNARK 电路（估算，`[待验证]`）** | 量级 `O(\|Q₀\|\|Q₁\|A)` 转移约束 **+ 闭包/不变式证书验证**；非已证明的约束规模 | 电路要证"不存在到达不一致状态的路径"，须给出可达集上界 `R` 的归纳不变式（初态∈`R`、`R` 对乘积转移封闭、`R` 中无不一致态），电路只验证该不变式而非枚举指数多条路径；`R` 最坏仍达 `\|Q₀\|·\|Q₁\|`，故"电路便宜"无保证 |
| **(V/S) NFA 路线** | 一般 NFA 判定 PSPACE-complete；电路化困难 | 按需子集算法难以直接算术化（`[待验证]`）；PSPACE 不推出证书大小下界（§3.1） |

### 2.3 Finite language

| 成本类型 | 估算 | 说明 |
| --- | --- | --- |
| **(G) 生成** | 枚举轨迹 `O(A^{T+1})` 每 `h`；共 `O(K·A^{T+1})` | 或构造最小 DFA（仍受子集构造影响） |
| **(V) 普通验证** | trie 逐项 `O(A^{T+1})`；最小 DFA 同构 `O(A·n)` | 依赖表示 |
| **(S) SNARK 电路** | 每条串 `O(T)` 约束 ⇒ `O(K·A^{T+1}·T)` | 对 `T` 指数敏感；不比普通算法便宜 |

### 2.4 全称化的统一成本

三种证书扩展到 `∀h₀∀h₁` 都需 `O(K²)`（逐对）或 `O(K)`（每 `h` 规范表示 + 全局比较）份子结构（`[数学推导]`）。SNARK 中递归聚合可把验证者成本压到 `O(log H)`，但**证明者总成本仍随 `K²` 增长**。

## 3. 成本对比的关键澄清（`[数学推导]`）

1. **普通 V ≠ SNARK S**：DFA 等价普通验证是多项式，但电路中每个状态对的转移都要分配约束，且需闭包/不变式证书（§2.2），"多项式"不等于"便宜"；反之 NFA 等价普通判定 PSPACE-complete，但电路若只验证给定的等价证书（如最小 DFA 同构）可能便宜——**复杂度类不等于电路规模**。**PSPACE 推论收紧（1D.2.1）**：NFA 等价 PSPACE-complete **不等于**已证明"不存在多项式大小、可多项式时间验证的正向证书"；若存在此类证书则该问题属于 NP，结合 PSPACE-completeness 将推出 `PSPACE=NP`——这是依赖复杂度类分离假设的推论，不是已证下界（`[数学推导]`）。§2.2 的 DFA 电路规模同样标为**估算**，非已证明的约束规模。
2. **生成 G 常被忽略**：子集构造、最小化、关系构造的成本落在证明者侧；若 G 已指数，SNARK 不改善，只转移成本形态。
3. **隐藏不是免费的**：所有证书隐藏都需承诺绑定 + 电路内打开验证，新增约束独立于证书本身的检查成本。
4. **完备性与规模反向**：互模拟（不完备）证书可简洁；语言证书（完备）规模对 `T` 指数——**这是本构造的观察，不是普遍下界**（`PROPERTY_REFINEMENT.md` §3.1）。

## 4. 面向 ZK 增益的横向判断（`[数学推导]`）

| 判断项 | State relation | Trace automata | Finite language |
| --- | --- | --- | --- |
| 数学内核是否标准 | 是（互模拟） | 是（DFA 等价） | 是（集合相等） |
| 隐藏后能否外部验证 | 能（但成本高） | 能（DFA 路线概念可行；电路成本为估算、需不变式证书，§2.2） | 能（但 `T` 指数） |
| 隐藏是否解决真实性 | 否 | 否 | 否 |
| 相对公开验证/签名的增益 | 无（除非硬隐藏需求） | 无（除非硬隐藏需求） | 无（除非硬隐藏需求） |
| 是否有新可证性质 | 无 | 无 | 无 |

**统一结论**（`[数学推导]`）：三种证书的数学内核都是标准自动机/互模拟理论；ZK 对三者都是封装层，不产生新可证性质。差异只在规模与完备性权衡，而这些差异在公开验证场景下可用普通算法解决，在隐藏场景下 ZK 可做但需未建立的硬需求支撑。

---

## 5. 小结

- 三证书在"目标性质"上统一于 `C_T`，差异在证明对象与完备性。
- 状态关系不完备但可简洁；自动机/语言证书完备但规模对 `T`/`N` 更敏感。
- 三种成本（生成/普通验证/SNARK 电路）必须分开；普通复杂度 ≠ 电路规模。
- 全称化 `|X_H|²` 与承诺绑定是三者共同的 ZK 成本，且不解决模型真实性。
- 面向 ZK 增益的横向判断一致：**内核标准、ZK 封装、无新可证性质** ⇒ 输入 STOP。
