# Phase 1D.2 — ZK 价值分析（本轮核心判断）

证据标记：`[定义]`、`[数学推导]`、`[标准结论]`、`[待验证]`。

> **本轮最重要的问题**：当我们已经能用普通形式化方法验证 Agent 的有界非干扰性时，究竟有什么**必须隐藏**、又**必须让外部验证者相信**的东西，以至于值得引入零知识证明？
>
> **预告结论**：分析后未找到不可替代的 ZK 增益。模型隐藏若非硬需求，普通承诺+签名/公开验证足够；若是硬需求，ZK 可做但成本与信任边界问题仍在，且"模型隐藏 ≠ 值得用 ZK"。详见 §8。

---

## 0. 场景设定

```
C_M = Commit(M)                               （隐藏有限 Agent 模型的承诺）
证明目标：∀x_L∈X_L, ∀h₀,h₁∈X_H : L_T(M,x_L,h₀) = L_T(M,x_L,h₁)
验证者可见：C_M、公开参数 (T, Λ, |X_L|, |X_H|, 电路模板)、证明 π、验证结果
验证者不可见：M 的转移结构、m_H、h₀,h₁ 的具体值、证书 I/自动机/语言表示
```

---

## 1. 模型哪些部分必须公开？

| 部分 | 是否必须公开 | 理由 |
| --- | --- | --- |
| 字母表 `Λ`、`T`、长度界 | **是** | 属于公开参数/电路模板；验证者需知道证明的命题是什么 |
| `X_L` 的编码、`\|X_L\|` | **是** | 全称量词的论域需公开，否则命题不明确 |
| `\|X_H\|`（高输入集合大小） | **是**（或公开承诺） | 全称覆盖范围的承诺；若完全隐藏，验证者无法确认证明覆盖了所有高输入 |
| 低输入 `x_L` 具体值 | 视场景 | 公开输入可在电路外；若涉密则入见证（但 NI 全称应对所有 `x_L` 成立） |
| 转移关系 `→` | 否（可隐藏） | 可承诺后作为见证；但检查约束需电路访问（承诺+查找论证） |
| `Init`、`Obs`、`Term` 的编码 | 否（可隐藏） | 同上；但 `Term` 取值域 `{RUN,DONE,STUCK}` 需公开 |
| 高输入 `h₀,h₁` 具体值 | 否（可隐藏） | 全称证明中应作为任意见证，不暴露具体值 |
| 证书（`I_k`/自动机/语言表示） | 否（可隐藏） | 证明者的见证 |

**结论**（`[数学推导]`）：必须公开的是**命题框架**（`Λ, T, |X_L|, |X_H|`, 电路模板）与**承诺 `C_M`**；模型内部结构可隐藏，但隐藏不改变命题框架必须公开这一事实。

---

## 2. 哪些部分可以隐藏？

可隐藏集合 = `{→, Init, Obs, Term 的具体编码, m_H, h₀,h₁, 证书结构}`。隐藏的技术手段：

- 把 `M` 的转移表承诺进 `C_M`（如 Merkle root 或多线性承诺）；
- 在电路内用**查找论证（lookup argument）**按 `(s,a)` 查询 `→`，不暴露未查询项；
- 证书（`I_k`/自动机转移）作为见证，仅约束其满足 Soundness 条件。

**代价**（`[数学推导]`）：每查询一次转移关系都要付出电路约束；∀后继匹配 (`STEP`) 与 ∀高输入对 (`INIT`) 意味着查询次数随 `|S|·|Λ̂|` 与 `|X_H|²` 增长。隐藏并非免费。

---

## 3. 证明者能否偷偷更换模型或缩小高输入集合？

这是**绑定（binding）问题**，分三种攻击（`[数学推导]`）：

### 3.1 更换模型（换一套 `M'` 使证明成立）

- 若 `C_M` 是**绑定承诺**，电路内每个转移查询都从 `C_M` 打开并验证路径 ⇒ 证明者不能换模型；
- 若查询未与 `C_M` 绑定（例如证明者自由选择转移值），则可换 ⇒ **soundness 漏洞**；
- **必需**：`C_M` 的绑定性 + 电路内打开验证 + 公开输入含 `C_M`。

### 3.2 缩小高输入集合（只证一部分 `h` 使命题平凡成立）

- `|X_H|` 公开且电路对 `h₀,h₁ ∈ X_H` 全称量化（遍历承诺的高输入域）⇒ 不能缩小；
- 若 `X_H` 的编码/大小不公开，或全称化由证明者自由给出的列表近似 ⇒ **可缩小**，命题退化为 B（单例）而非 C（全称）；
- **必需**：`X_H` 的域大小公开承诺 + 电路内全称遍历或等价约束。

### 3.3 缩小可观察语言（漏报轨迹）

- 若语言证书（`I_k`/自动机/trie）的后继集合由证明者自由提供且未与 `C_M` 绑定 ⇒ 可漏后继 ⇒ 假阳性；
- **必需**：∀后继全称 + 承诺绑定（Phase 1D.1 的 (STEP) 双向匹配已覆盖这一点）。

**结论**（`[数学推导]`）：三种攻击都可被"承诺绑定 + 电路内全称遍历 + 公开域大小"堵住，但**这些约束本身就是电路成本**，且绑定只保证"对某个被承诺模型成立"，不保证该模型是真实 Agent。

---

## 4. 如何保证证明对应同一个模型承诺？

**机制**（`[数学推导]`）：
1. 公开输入包含 `C_M`；
2. `M` 的结构（`→` 等）作为见证，电路内计算 `Commit(M)` 并断言 `= C_M`；
3. 每次转移查询附带打开证据，由电路验证其与 `C_M` 一致；
4. 全称量词遍历的 `h₀,h₁` 来自公开承诺的高输入域，不由证明者自选。

**残余缺口**（`[待验证]`）：
- 相同 `C_M` 可对应多个模型（承诺隐藏），验证者无法区分 `M` 与碰撞的 `M'`（依赖承诺绑定性）；
- 即便绑定，`C_M` 由谁生成？若由被审计方生成，被审计方可选一个**满足 NI 但不忠实于其真实 Agent** 的模型 `M` 来承诺——这是**模型来源信任问题**，ZK 无法消除（Phase 1C 停止条件 5、Phase 1D 边界声明）。

## 5. 是否必须把整个自动机编码进电路？

分三种证书（`[数学推导]`）：

| 证书 | 电路内必须编码的内容 | 规模 |
| --- | --- | --- |
| 状态关系 `I_k` | `I₀..I_T` 的判定 + ∀后继匹配查询 | `O(\|S\|²·T·\|Λ̂\|)` 级别的约束（依赖 `I` 表示） |
| DFA 自动机 | 两个 DFA 转移表 + **可达集上界不变式**（非仅"路径约束"） | `O(\|Q₀\|·\|Q₁\|·\|Λ̂\|)` 仅为**估算**；`Qᵢ` 最坏 `2^{\|S\|(T+1)}`；电路规模未证明（`[待验证]`） |
| 有限语言 trie | 每条串的路径 + 逐项比较 | `O(轨迹数 · T)` |

**DFA 电路成本的边界（1D.2.1 收紧）**：上表 DFA 行的量级只是估算。普通乘积可达性判定的是"**存在**一条到达不一致状态的路径"；在电路中要证明"**不存在**这样的路径"，不能只写"乘积可达性路径约束"，而须给出可验证的闭包/不变式证书——例如可达集上界 `R`，满足初态∈`R`、`R` 对乘积转移封闭、`R` 中无不一致态——电路验证该不变式而非枚举所有路径。`R` 最坏仍含 `|Q₀|·|Q₁|` 个状态，故不能从"普通验证是 P"推出"SNARK 电路便宜"；该成本记为 `[待验证]` 估算。

**能否只编码部分？** 有两条可能路径（`[待验证]`）：
- **承诺 + 查找论证**：只编码查询逻辑，转移表存在电路外承诺中，按查询打开 ⇒ 电路大小随查询数而非全表；但查询数仍随全称量词增长。
- **分块/递归**：把每个 `(h₀,h₁)` 对的检查做成子证明，用递归 SNARK 聚合 ⇒ 主电路大小固定，但总证明成本 = 对数 × 子证明成本，不减少总工作量。

**结论**（`[数学推导]`）：不必"整表明文入电路"，但**必须编码查询/验证逻辑并与承诺绑定**；递归 SNARK 只改善验证者工作量与证明大小，不减少证明者总成本。

## 6. 普通公开验证、签名证明、Lean 证明是否已经足够？

### 6.1 公开验证（`[数学推导]`）

若模型 `M` 可公开：
- 状态互模拟检查：多项式；
- DFA 等价：乘积可达性多项式；
- 最小 DFA 同构：`O(|Σ|n log n)`。
⇒ **普通验证完全足够，且比 SNARK 便宜几个数量级**。ZK 在模型可公开时**零增益**。

### 6.2 签名 + 可信第三方（`[数学推导]`）

若需隐藏模型但**存在可信验证方**：
- 可信方验证 `M` 满足 `C_T`，对 `(C_M, "C_T holds", 参数)` 签名；
- 外部只验签名 + `C_M` ⇒ 无需 ZK，成本极低。
⇒ ZK 仅在**无单一可信方**且**必须隐藏**时有意义。这个前提条件强于"模型可以隐藏"。

### 6.3 Lean 机器检验（`[标准结论]` + `[数学推导]`）

- Lean 可机器检验有限模型上的全称性质（如 LLMbda 的概率 NI，Phase 1C 核验）；
- 但 Lean 证明需要**公开模型定义**，且验证者是本地 Lean 内核 ⇒ 不满足"隐藏模型 + 外部轻量验证"；
- Lean 证明可作为**证明者侧的正确性保障**，与 ZK 组合（"证明已机检的命题的简洁 ZK 证明"），但这增加而非减少成本。

### 6.4 三种方式的适用矩阵

| 场景 | 最合适工具 | ZK 是否必要 |
| --- | --- | --- |
| 模型可公开 | 普通算法 / Lean | 否 |
| 模型需隐藏 + 有可信方 | 可信方签名 | 否 |
| 模型需隐藏 + 无可信方 + 外部轻量验证 | ZK | **是**（唯一 ZK 必要场景） |
| 模型需隐藏 + 外部验证 + 还需确认模型忠实真实 Agent | ZK **也不能**解决真实性 | 无解（信任边界外） |

## 7. 关键区分："模型可以隐藏" ≠ "值得使用 ZK"

**逻辑分解**（`[数学推导]`）：

```
值得用 ZK  =  (必须隐藏模型) ∧ (必须外部可验证) ∧ (无可信方) ∧ (硬需求非软偏好) ∧ (承诺绑定/全称化成本可接受)
```

逐项评估：

1. **必须隐藏模型**：本路线未建立硬需求。Phase 1C 停止条件 5（"隐藏会话图是实际应用硬需求"）未闭合；本轮三种证书分析也未产生新的硬需求证据（`[待验证]`）。
2. **必须外部可验证**：审计场景可能成立，但若模型可由可信审计方验证并签名，则不需 ZK。
3. **无可信方**：未在任务中给出；默认不能假设。
4. **硬需求非软偏好**："隐藏起来更稳妥"是软偏好；"泄露会造成实质损害且有外部验证义务"才可能构成硬需求——未建立。
5. **成本可接受**：全称化 `|X_H|²` + 承诺绑定查询 + 子集构造（若走 DFA 路线）使电路成本显著；且承诺只绑定"被承诺模型"，不解决真实性。

**结论**（`[数学推导]`）：五个合取项中至少三项（1、4、5）当前不成立或未建立 ⇒ **不能**得出"值得用 ZK"。

## 8. 对本轮最终问题的直接回答

> 问题：当我们已经能用普通形式化方法验证 Agent 的非干扰性时，究竟有什么必须隐藏、又必须让外部验证者相信的东西，以至于值得引入零知识证明？

**回答**（`[数学推导]`）：

1. **可能必须隐藏的**：Agent 的转移结构、秘密输入、内部信息流——这些若泄露确有损害（`[待验证]`：损害是否达到"硬需求"未建立）。
2. **必须让外部验证者相信的**：`C_T(M)` 对某个模型成立——但这个"某个模型"若由被审计方自选并承诺，外部验证者真正需要的"真实 Agent 满足 NI"**并未被证明**。
3. **不可替代的 ZK 增益**：仅当"隐藏 + 外部验证 + 无可信方 + 硬需求"同时成立时存在；当前四项未同时建立。
4. **因此**：ZK 在这里是**条件性可选工具**，不是不可替代的研究核心。把它装进 Halo2 不会自动产生研究价值，只会增加工程成本与新的信任假设。

---

## 9. 小结与裁决输入

- 必须公开的：`Λ, T, |X_L|, |X_H|`, 电路模板, `C_M`；
- 可隐藏的：`→, Init, Obs, Term` 编码, `m_H`, `h₀,h₁`, 证书结构；
- 绑定要求：承诺绑定 + 电路内打开验证 + `X_H` 全称遍历（否则可换模型/缩小高输入/漏报）；
- 三种替代（公开验证/签名/Lean）在各自场景下更便宜或更合适；
- **ZK 必要性前提未建立，且真实性问题 ZK 无解**；
- 输入 `DECISION.md`：ZK 增益不足以支撑继续投入 Halo2 ⇒ 倾向 STOP。
