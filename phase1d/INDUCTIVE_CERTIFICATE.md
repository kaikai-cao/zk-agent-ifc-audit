# Phase 1D — D3：双状态归纳不变量构造

证据标记：`[定义]`、`[数学推导]`、`[待验证]`。本文件给出候选证书，可靠性证明在 `SOUNDNESS_PROOF.md`。

---

## 1. 目标与设定

目标：对 `FINITE_AGENT_MODEL.md` 的有限模型 `M`，构造一个比枚举 `|X_H|²` 对执行更紧凑的证书，使验证者相信 `C_T(M)`（有界、观察集相等的非干扰性），而不看到敏感模型细节。

候选关系：

```
I(s₀, s₁) ⊆ S × S
```

其中 `s₀` 来自高输入 `h₀` 的执行，`s₁` 来自 `h₁` 的执行（同 `x_L`）。**`I` 本身是证明者的秘密见证**，验证者只见其承诺与约束检查结果。

记号：`Obs⁺(s) = (buf(s), term(s))`（把终止类别并入观察，D2 §2.5）。

## 2. Sync 的严格定义（本文件核心）

### 2.1 不能定义成"两条轨迹执行完全相同的动作"

理由（`[数学推导]`）：
- 秘密输入必然导致 `read_H` 读到的值不同；若要求动作逐字相同，则 `A_I` 中的秘密相关动作无法配对，证书无法建立。
- 低观察只关心 `A_L`；`A_I` 的差异被 AM1 隐藏。因此 Sync 应**只在低可见层要求一致**，在内部层允许不同。

### 2.2 定义

```
Sync(a₀, a₁) = 1  ⟺
   (1) a₀ ∈ A_L  ⇒  a₁ = a₀        （低动作必须逐字相同，含公开参数）
   (2) a₁ ∈ A_L  ⇒  a₀ = a₁        （对称；防止一侧悄悄少输出）
   (3) a₀ ∈ A_I  ⇔  a₁ ∈ A_I       （内部动作允许不同，但类型必须同类）
   (4) a₀ = τ  ⇔  a₁ = τ           （静步对齐，用于长度不同的执行）
```

推论（`[数学推导]`）：
- 条件 (1)(2) 保证两条执行发出的低动作序列**逐位相同**；
- 条件 (3) 保证 `read_H`/`secret_call` 只能与同类内部动作配对，不能冒充低动作；
- 条件 (4) 保证**一侧多出的内部步不能单方面用别人的静步抵消**——但允许两侧各自插入等量静步（`τ` 对 `τ`），配合 `δ(s,τ) ∋ s` 的 stuttering 公理即可对齐不同长度（见 §4）。

### 2.3 五个具体问题逐一回答

**Q1 哪些动作必须同步？**
所有 `A_L`：`out(v)` 的 `v` 必须相同；`pub_call(t,args_L)` 的 `t` 与 `args_L` 必须逐字相同；`halt` 必须同时发生。理由：这些动作进入 `obs`，不一致即违反 `C_T`。

**Q2 哪些动作可以不同但低观察相同？**
`A_I` 全部：`read_H` 读到的值、`secret_call(t,args_H)` 的工具与参数、`internal` 的内部更新都可以不同。条件 (3) 只要求"同为内部动作"。AM1 保证它们不改 `buf/m_L/term`。

**Q3 工具调用参数是否属于低观察？**
按可见性分类，不是按"是不是工具"分类：
- `pub_call(t,args_L)`：`t, args_L` ∈ `obs`，必须相同；
- `secret_call(t,args_H)`：`t, args_H` 均不在 `obs`，可不同；
- 混合情形（工具身份公开、参数秘密）必须拆成两步：`pub_call(t)` + `secret_set(args_H)`，否则 Sync 定义失效。这是模型的表达约束，不是密码学问题。

**Q4 非确定性工具返回如何配对？**
不能用单状态转移，必须用集合级条件（§3 的 Step (a)(b)）：对一侧的每个后继，另一侧必须存在 `I` 相关的后继，反之亦然。这是 bisimulation 式的"双向全关系"，保证 `ObsSet` 相等而非单向包含。

**Q5 一边终止、另一边继续怎么办？**
`Obs⁺` 含 `term`，故 `I(s₀,s₁)` 要求 `term(s₀)=term(s₁)`；一边 `DONE` 另一边 `RUN` 时 `I` 不成立，证书无法通过。配合 `halt` 属 `A_L` 且必须同步，`halt` 只能同时发生。若一侧因无可用动作进入 `STUCK`，则 `term` 也不同，`I` 失效——这是正确拒绝（`C_T` 也失败）。

## 3. 三个条件

### 3.1 初始化条件

```
(Init)  ∀ x_L ∈ X_L, ∀ h₀,h₁ ∈ X_H :
          I( Init(x_L,h₀), Init(x_L,h₁) )
```

**关键**：这是对**所有** `h₀,h₁ ∈ X_H` 的全称条件，不是证明者挑选的一对。若证书只对挑出的对成立，则只证明 B，不证明 C（`[数学推导]`；对应任务包阻断项 2）。在电路中这意味着 `h₀,h₁` 必须是见证中的任意值，且 Init 条件对它们的约束不得依赖其具体取值（只依赖 `m_H` 被隔离这一结构）。

### 3.2 归纳保持条件（集合级，非单值）

```
(Step)  ∀ s₀,s₁ : I(s₀,s₁) ∧ Sync(a₀,a₁)
          ∧ a₀ ∈ Act(s₀), a₁ ∈ Act(s₁) ⇒
            (a) ∀ s₀' ∈ δ(s₀,a₀) : ∃ s₁' ∈ δ(s₁,a₁) : I(s₀',s₁')
            (b) ∀ s₁' ∈ δ(s₁,a₁) : ∃ s₀' ∈ δ(s₀,a₀) : I(s₀',s₁')
```

(a)(b) 双向是**可达性集合相等**所必需：仅有 (a) 得到 `ObsSet(s₀) ⊆ ObsSet(s₁)`，不足以得到 `C_T` 要求的相等。

### 3.3 观察一致条件

```
(Obs)   ∀ s₀,s₁ : I(s₀,s₁) ⇒ Obs⁺(s₀) = Obs⁺(s₁)
       即 buf(s₀)=buf(s₁) ∧ term(s₀)=term(s₁)
```

## 4. 三种不变量形式必须区分（任务包明确要求）

| 形式 | 定义 | 强度 | 适用 |
| --- | --- | --- | --- |
| **全局不变量** | `I ⊆ S×S` 对**所有**状态对成立，无步数上限 | 最强；可能根本不存在 | 理想化证明 |
| **可达不变量** | `I` 只要求对从初始态经 `Sync` 锁步可达的对成立 | 较弱；soundness 仍成立（证明只走可达路径） | 实际候选 |
| **有界归纳证书** | `I₀,…,I_T`，`I_k` 只覆盖剩余 `≤ k` 步；`I₀ ⇒ Obs⁺` 相等；`I_{k+1}` 用 `I_k` 做 Step | 最弱且有限；直接对应 `C_T` | **本阶段目标** |

**有界证书递归定义**（`[定义]`）：

```
I₀(s₀,s₁)   = ( Obs⁺(s₀) = Obs⁺(s₁) )
I_{k+1}(s₀,s₁) = I₀(s₀,s₁)
               ∧ ∀ a₀,a₁ : Sync(a₀,a₁) ∧ a₀∈Act(s₀) ∧ a₁∈Act(s₁)
                    ⇒ (a') ∀s₀'∈δ(s₀,a₀) ∃s₁'∈δ(s₁,a₁): I_k(s₀',s₁')
                      (b') ∀s₁'∈δ(s₁,a₁) ∃s₀'∈δ(s₀,a₀): I_k(s₀',s₁')
```

目标：`I_T(Init(x_L,h₀), Init(x_L,h₁))` 对所有 `x_L,h₀,h₁` 成立。

**注意**：`I_k` 不是"k 步后的状态"，而是"还剩 k 步预算时的允许状态对"。这个索引方式让 stuttering 与终止自然落入递归。

**stuttering 公理**（`[定义]`，补充 D2）：`∀s : s ∈ δ(s, τ)`。由此两侧可各自插入任意数量 `τ`，对齐不同长度执行（Sync (4) 保证 `τ` 对 `τ`）。

## 5. 证书规模与表示（`[数学推导]`，细节见 COMPLEXITY_COMPARISON.md）

证书需要给出：
1. 每个 `I_k` 的表示（显式集合 `O(|S|²T)`，或判定电路/决策表）；
2. 对每个 `(s₀,s₁,k)` 的 Step 见证：后继配对函数 `f : δ(s₀,a₀) → δ(s₁,a₁)` 及逆配对。

最关键的可压缩点：若 `I` 有**简洁语义描述**（例如"I ⟺ buf 与 term 相等，m_H 任意"），则 `I` 的规模与 `|S|²` 无关，Step 检查也可按结构做而非逐状态枚举。这是"比枚举更紧凑"的唯一来源；若 `I` 必须显式列出 `|S|²T` 项，则相对枚举 `|X_H|²` 对未必有优势。

## 6. 不变量必须隐藏什么，以及隐藏的代价

- `I_k` 编码了"哪些状态被认为低等价"，泄露它会暴露模型的状态结构与工具分支；
- `δ` 的转移结构本身可能是敏感模型细节；
- 在 ZK 方案中，`I` 与 `δ` 都作为见证提交，验证者只见承诺与约束结果（`[待验证]` 需电路固定模板、承诺绑定）；
- **诚实缺口**：验证者看不到模型，就只能相信"某个被承诺的模型满足约束"，而无法确认该模型就是实际 Agent 的忠实抽象。这是模型来源信任问题，ZK 不解决它（`[数学推导]`；对应任务包阻断项 3 的一半）。

---

## 7. 小结

- Sync 只在低可见动作上严格，在内部动作上宽松；静步对齐长度，集合级双向配对保证观察集相等。
- 三个条件 Init/Step/Obs 直接针对 `C_T` 的量词结构，其中 Init 必须覆盖**全部**高输入对。
- 三种不变量形式不可混用；本阶段目标是有界归纳证书 `I₀..I_T`。
- 紧凑性取决于 `I` 是否有简洁描述；隐私收益取决于能否把 `I` 与 `δ` 作为见证隐藏，但模型真实性仍不在证明内。
