# Phase 1D — D5：三种证明路径的复杂度比较

证据标记：`[定义]`、`[数学推导]`、`[原文核验]`、`[假设]`、`[待验证]`。全部复杂度**依赖模型表示方式**，不笼统说"有限状态=指数"。

---

## 1. 参数与表示方式

```
H = |X_H|,  L = |X_L|,  N = |S|,  E = |δ| (转移边数),  B = 最大分支因子
T = 有界步数,  Ac = |A|,  K = 证书不变量规模（显式= N²(T+1)，紧凑视表示而定）
```

三种模型表示（`[定义]`）：

| 表示 | 描述 | 大小 | 单步求值成本 |
| --- | --- | --- | --- |
| **R1 显式转移表** | `δ` 以 `(s,a)→{s'}` 表给出 | `O(N·Ac + E)` | `O(1)` 查表 |
| **R2 紧凑状态转移电路** | `δ` 由算术电路 `C_δ` 计算，状态编码为 `⌈log N⌉` 位 | `O(|C_δ|)` | `O(|C_δ|)` |
| **R3 程序描述的状态机** | `δ` 由小程序/循环体给出（如 D2 的六元组更新） | `O(|prog|)` | `O(|prog|)` |

**关键区分（`[数学推导]`）**：复杂度不能只看 `N`。R1 下表查找便宜但内存大；R2 下电路小但每步求值贵；R3 下若程序有循环，单步成本与循环体成正比，与 `N` 弱相关。

---

## 2. 三条路径

### 2.1 路径 P1：显式枚举

对每个 `(h₀,h₁)` 对、每条执行做展开比较。

```
工作量 ∝ H² · (期望执行条数) · T · 单步成本
```

| 表示 | 证明者工作量 | 验证者工作量 |
| --- | --- | --- |
| R1 | `O(H² · B^T · T)` 查表 + 观察比较 | 同量级重算，或验 `H²` 个证明 |
| R2 | `O(H² · B^T · T · |C_δ|)` | 同上 |
| R3 | `O(H² · B^T · T · |prog|)` | 同上 |

- 若 `δ` 确定（`B=1`），降为 `O(H² · T · 单步成本)`。
- 非确定下 `B^T` 是主要爆炸源；`C_T` 要求观察集相等，需枚举两条执行的所有分支。
- **优点**：概念最简单，无需证书设计；**缺点**：与 `H²`、`B^T` 成正比。

### 2.2 路径 P2：双轨迹执行 / self-composition

把两条执行写进同一个证明（product program），一次证明覆盖一对 `(h₀,h₁)`；若要覆盖全部对，仍需 `H²` 次或把 `h₀,h₁` 作为见证并全称化。

```
电路规模 ∝ 2 · T · 单步成本 + 比较逻辑
```

| 表示 | 证明者工作量 | 验证者工作量 |
| --- | --- | --- |
| R1 | `O(2T + E查表)` 每对 | `O(1)` 验一个证明（SNARK） |
| R2 | `O(2T · |C_δ|)` 每对 | `O(1)` |
| R3 | `O(2T · |prog|)` 每对 | `O(1)` |

- 与 self-composition 的经典做法一致（`[原文核验]`：见 `RELATED_WORK_AUDIT.md` 关于 product programs/self-composition 的讨论）。
- **隐私代价**：两条轨迹的执行细节进入见证；若用 ZK 隐藏，电路仍随 `T` 线性增长，且成对构造要求证明者持有两整套执行。
- **无法自动全称化**：若 `(h₀,h₁)` 由证明者选，只证 B；要证 C 必须引入"对 `X_H²` 全称"的机制，回到枚举或证书。

### 2.3 路径 P3：归纳证书（本阶段候选）

提交 `I₀..I_T` 及后继配对见证，检查 Init/Step/Obs。

```
电路规模 ∝ |I| · (Init 检查) + |I| · Ac² · (Step 检查) + |I| · (Obs 检查)
```

| 表示 | 证明者工作量 | 验证者工作量 |
| --- | --- | --- |
| R1（显式 I） | `O(N²(T+1) · Ac² · B)` | `O(1)` 验一个证明 |
| R2（电路 I） | `O(|C_I| · Ac² · |C_δ|)` | `O(1)` |
| R3（程序 I） | `O(|I_prog| · Ac² · |prog|)` | `O(1)` |

**紧凑性的真正来源（`[数学推导]`）**：

- 若 `I` 有简洁谓词（如"I ⟺ buf 与 term 相等，m_H 任意"），则 `|C_I| ≪ N²`，P3 的工作量可与 `H` **无关**（因为 Init 检查对 `h₀,h₁` 全称，不枚举它们）；
- 这是 P3 相对 P1 的唯一实质优势：**把 `H²` 的枚举换成 `|I|` 的证书检查**；
- 若 `I` 必须显式列出 `O(N²T)` 项，P3 可能因 `N²` 大于 `H²` 而更差。

---

## 3. 三种表示下的详细对照表

| 维度 | P1 枚举 | P2 self-composition | P3 归纳证书 |
| --- | --- | --- | --- |
| R1 显式表：证明者 | `H²B^TT` | `2T` 每对 × `H²` 对 | `N²T·Ac²B` |
| R1 显式表：验证者 | 重算或 `H²` 次验 | `O(1)` 每对 | `O(1)` |
| R2 紧凑电路：证明者 | `H²B^TT·|C_δ|` | `2T·|C_δ|` 每对 | `|C_I|·Ac²·|C_δ|` |
| R2 紧凑电路：验证者 | 同左 | `O(1)` | `O(1)` |
| R3 程序状态机：证明者 | `H²B^TT·|prog|` | `2T·|prog|` 每对 | `|I_prog|·Ac²·|prog|` |
| 全称覆盖 | 显式枚举 `H²` | 需额外机制 | Init 条件全称覆盖 |
| 见证含什么 | 每条执行 | 两条执行 + 高输入 | `I` + 后继配对 |
| 隐私暴露面 | 全部轨迹 | 两条轨迹 | `I` 形状 + `δ` 结构 |
| 主要瓶颈 | `H²·B^T` | 每对开销 × 对数 | `I` 的表达能力/规模 |

## 4. 何时哪条路径更优（`[数学推导]` + `[假设]`）

```
P3 优于 P1  ⟺  |I| · Ac² · 单步成本  <  H² · B^T · T · 单步成本
```

- 当 `H` 大（秘密输入空间大）、`B^T` 大（非确定）、`T` 大，且 `I` 有简洁描述时，P3 明显优；
- 当 `H` 小、`δ` 确定、`I` 必须显式列出时，P1 更简单；
- P2 是"每对"的折中：若只需向验证者证明特定挑战对（B 性质），P2 最自然；若要 C，P2 缺乏全称机制。

**不宣称普遍优势**：以上均为结构复杂度，非实测；实际常数依赖电路实现、域大小、承诺方案（`[待验证]`）。

---

## 5. 证书规模的硬下限（`[数学推导]`）

由 `SOUNDNESS_PROOF.md` §4.2 的不完备性分析：

- 若要求对**所有**满足 `C_T` 的模型完备，`I` 必须是足够宽的二元关系（接近最大 bisimulation），规模 `Ω(N²)`；
- 若要求 `|I| = O(poly)`，则存在满足 `C_T` 但证书无法证明的模型；
- 因此"紧凑 + 完备"不可兼得；P3 的实用价值只在"对目标模型类，简洁 `I` 恰好够用"时成立。

---

## 6. 隐私与成本的关系（`[数学推导]`）

- 隐藏 `I` 与 `δ`：需要把它们作为见证并承诺；电路必须固定模板，不能随秘密模型变化，否则电路形状泄露模型；
- 固定模板意味着电路按最坏情况 `N_max`、`T` 构建，可能抵消 P3 的紧凑性收益；
- 若 `I` 简洁到可用小程序表示，固定模板可以只编码程序大小上限，隐私与紧凑可兼得——但这是原型层问题，本阶段不验证（`[待验证]`）。

---

## 7. 结论

- 复杂度排序**不是固定的**：取决于 `H, B, T, N` 与 `I` 的表示；
- P3 的相对优势来自"用 `I` 的全称检查替代 `H²` 枚举"，且要求 `I` 有简洁描述；
- P3 不具备对全部 `C_T` 模型的完备性；紧凑性与完备性存在张力；
- 隐私需求（隐藏 `I`/`δ`）可能与固定电路模板冲突，需在原型前评估。
