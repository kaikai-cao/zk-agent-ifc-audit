# 安全模型与信任边界

## 1. 参与方

| 角色 | 能力 | 信任假设 | 不信任的部分 |
| --- | --- | --- | --- |
| Agent runtime | 产生事件、调用工具 | 配置固定；不被证明关系验证 | 输出内容语义、是否遵循提示 |
| Collector（可信采集器） | 观察事件、构造 G、编码、计算盲化承诺 `C`、签名 | 正确记录其观察到的事件；私钥不泄露 | 可能被对手诱导漏记/错记（不在证明内） |
| Prover | 持有 G、标签、S、Merkle 路径 | 可任意选择见证；可能被攻陷 | 不能破坏 SNARK soundness |
| Verifier | 持有采集器公钥、策略定义、公开输入 | 正确执行验签与 Verify | 不获得见证；不重跑 Agent |
| Policy authority | 发布 `policy_id -> 策略版本` | 策略定义权威且版本固定 | 不由证明产生策略真值 |

## 2. 信任边界分层

### 2.1 图内容信任（被 ZKP 削减）

验证者不需要信任证明者提供的图内容；证明者若提交不满足关系的 G，无法通过验证。零知识性保证验证者看不到 G 的节点、边、标签、S 形状。

### 2.2 采集器完整性信任（未被 ZKP 消除）

验证者仍须相信采集器：

- 观察到全部相关事件；
- 正确分配来源标签；
- 没有把 High→Low 边从图中删除；
- 私钥未泄露；签名方案与 nonce 管理正确。

**反例 D（漏边）**：采集器漏记 `High -> Low` 边后得到 `G_clean`，证明者可对 `G_clean` 生成有效证明。验证者看到 `Verify=1` 只能得出“被承诺图合规”，不能得出“原执行无该边”。

**反例 E（错误标签）**：若采集器把 confidential source 错标为 Low，则闭包条件更容易满足；证明关系没有独立的标签来源真值锚点。标签真实性属于采集器与策略权威的信任边界。

### 2.3 策略语义信任（未被 ZKP 消除）

`policy_id` 只指向公开策略版本。证明验证的是该策略定义的图谓词（本阶段为两元素格上的前向闭包），不证明策略本身正确、适用或未被替换。策略版本应通过带外固定/透明日志锚定。

### 2.4 运行时执行信任（未被 ZKP 消除）

ZKP 不证明工具调用真实发生、调用参数未被篡改、结果未被伪造。若需要这些性质，需要额外的执行收据、TEE 远程证明或可验证执行记录；那是系统工程任务，不能继承本项目的 GO 假设。

## 3. 对手模型

### 3.1 恶意证明者

目标：让 `Verify(x, π)=1`，即使其隐藏图不满足关系，或使验证者相信其图具有某种性质。防御：SNARK soundness + 承诺绑定 + 公开输入域分离。假设对手多项式有界，不利用参数生成后门（本原型使用可复现透明参数/固定 setup，见 Phase 1B 报告）。

### 3.2 诚实但好奇的验证者

目标：从 π 和公开输入推断 G 的细节。防御：零知识性。验证者只看到 `C / policy_id / session_id / nonce / collector_id`（Phase 1B.1：`C` 为带随机盲化的承诺，不再公开可枚举的 `root_G`）。注意：若 G 规模、策略或公开元数据本身包含敏感信息，零知识不隐藏公开输入；设计时应把可公开信息最小化。

### 3.3 被攻陷的采集器/标签来源

目标：提交不完整或错标的图。防御：**不在本证明关系内**。可缓解机制：多采集器交叉签名、TEE 中的采集器、外部审计日志；均属未来系统工程，不宣称已解决。

### 3.4 重放与跨会话混淆

验证者 nonce 与 session_id 均为公开输入并参与见证绑定；同一证明在其他 nonce/session 下不应验证通过。Phase 1B 用错误实例拒绝测试验证这一点；但 nonce 的**唯一性与消费状态**由验证者/协议层负责，SNARK 不提供状态。

## 4. 性质清单（严格边界）

| 性质 | 本原型 | 依据/边界 |
| --- | --- | --- |
| 承诺图满足 Trace-IFC（N2） | 是（电路内） | 闭包条件 + 编码约束 |
| 证明绑定公开 root/session/nonce/policy | 是（电路内） | 公开输入约束 |
| 不泄露 G 的节点/边/标签/S | 是（协议层） | SNARK zero-knowledge；不做实际隐藏性统计声明 |
| 采集器未漏记 | 否 | 信任模型；反例 D |
| 标签来源真实 | 否 | 信任模型；反例 E |
| 经典两运行 NI | 否 | 量词不同；见 `PROBLEM_DEFINITION.md` |
| 运行时调用真实发生 | 否 | 需外部收据/TEE |
| 策略正确/适用 | 否 | 策略权威带外固定 |

## 5. 对“签名基线”的诚实对照

明文图检查器与承诺+签名基线都把图交给验证者（或至少由验证者重算谓词）；它们减少的是“证明计算信任”，不减少图内容披露。ZK 基线减少的是“验证者看到图或信任证明者给的图”，但增加证明生成成本，并且不减少采集器信任。详细成本见 `experiments/baselines/`。

## 6. Phase 1B.1.2 后的对手模型修正

修复前的电路允许恶意证明者把“承诺 preimage advice”和“谓词检查 advice”拆开：节点类型/标签、节点位置、边端点、Poseidon 域、empty padding 以及 crossbar 初始累加器均可被分别操纵。由此得到的结论是：1B.1 的“承诺图满足 Trace-IFC”声明在电路层并未被建立，而不是只存在实现细节问题。

修复后：

- 恶意证明者必须让同一组受约束字段同时满足闭包谓词与 Merkle/Poseidon 承诺编码；cap=50 的五类恶意 witness 与四类真实负向证明均被拒。
- verifier 不读取 `public.json` 自称的采集器公钥，而从独立 allowlist 取公钥；`collector_id` 由公钥按固定 SHA-256 前缀规则重新计算。测试 allowlist 中的确定性密钥仅为公开 fixture。
- blind 由 OS CSPRNG 在证明进程内采样（32 字节输出清最高两位，254-bit 采样空间），不经过 CLI seed，也不写入 `public.json`；`density`/`active_edges` 不属于 SNARK public inputs，只写入 benchmark 辅助 `meta.json`，但该文件已随证据提交到公开 Git 仓库（合成数据，非真实会话秘密）。

仍未解决：采集器是否漏记/错标、策略版本是否权威、运行时事件是否真实发生、nonce 是否由协议层唯一消费。零知识性与盲化承诺也不隐藏 `cap`、策略 ID、会话 ID、nonce、采集器 ID 以及“存在一次合规证明”这一事实；本阶段不声称承诺的统计隐藏性形式化证明。

## 7. 三命题严格区分（Phase 1B.1.3 / E）

以下三个命题必须分开陈述，不得互相推广：

| 命题 | 含义 | 本原型是否证明 |
| --- | --- | --- |
| **Graph compliance** | 给定图 `G` 满足 Trace-IFC 谓词（本阶段为两元素格上的前向闭包） | **是**：cap=50 正向证明通过、四类负向证明被拒、承诺 preimage 与谓词字段由电路绑定 |
| **Trace completeness / authenticity** | 给定图完整、真实地反映 Agent 实际执行（无漏记、无错标、事件确曾发生） | **否**：依赖可信 collector；反例 D（漏边）、E（错标）成立；证明关系没有独立的执行真值锚点 |
| **Runtime enforcement** | Agent 的实际执行被强制限制在策略允许范围内 | **否**：需执行收据 / TEE 远程证明 / 可验证执行记录；不继承本项目结论 |

补充回答任务包 E 的逐项核对：

1. Trace-IFC 谓词覆盖**显式数据流**（节点标签 + 边的前向闭包）；
2. **不覆盖控制依赖/隐式流**（未建模的控制边、语义因果不在关系内）；
3. 图由可信 collector 采集——这是**信任假设**，不是被证明性质；
4. 标签来自 collector/策略权威，**标签真实性未被证明**（反例 E）；
5. collector **可能漏记节点或边**（反例 D），证明层不可检出；
6. Agent runtime 是否按被记录的工具调用执行——**未被证明**，证明只作用于已记录的图；
7. 证明只能证明"给定图合规"，**不能证明图完整或真实，也不能证明运行时执行可信**。

`Verify=1` 的语义严格等于命题 1。任何把它表述为命题 2 或 3 的说法都超出证据。详见 `experiments/phase1b1_3/RESULTS.md` §7。
